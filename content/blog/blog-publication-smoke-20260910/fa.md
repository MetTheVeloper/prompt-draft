# Prompt Draft در عصر GPT‑Image‑2.5  
## وقتی پرامپت‌نویسی از «یک متن بلند» به یک سیستم طراحی تبدیل می‌شود

در چند سال اخیر، کیفیت مدل‌های تولید تصویر آن‌قدر سریع بالا رفته که مسئله‌ی اصلی دیگر فقط این نیست که «مدل می‌تواند تصویر خوبی بسازد یا نه». سؤال مهم‌تر این شده است: **چطور می‌توان خواسته‌ی انسانی را طوری به مدل منتقل کرد که نتیجه دقیق‌تر، قابل‌تکرارتر و قابل‌کنترل‌تر باشد؟**

Prompt Draft از دل همین سؤال شکل گرفت.

من Prompt Draft را به‌عنوان یک «پرامپت‌نویس خودکار» صرف طراحی نکردم. ایده از ابتدا این بود که بین **تصور ذهنی کاربر** و **زبان قابل‌فهم برای مدل تصویر** یک لایه‌ی ساختاری ایجاد شود؛ لایه‌ای که تصمیم‌های مهم را از هم جدا کند، تعارض‌ها را کم کند و اجازه بدهد یک ایده بدون تبدیل شدن به یک پاراگراف شلوغ و مبهم، به مجموعه‌ای از دستورهای روشن تبدیل شود.

ورود **ChatGPT Images 2.5** در ۸ سپتامبر ۲۰۲۶ این رویکرد را برای من جالب‌تر کرد. OpenAI در معرفی رسمی این نسل روی چند قابلیت مشخص تأکید کرده است: جزئیات شارپ‌تر، ویرایش دقیق‌تر، نور طبیعی‌تر، بافت‌های غنی‌تر، حفظ بهتر سوژه در تصاویر مرجع، ثبات بیشتر در ویرایش‌های چندمرحله‌ای و تا ۵۰٪ کاهش latency نسبت به Images 2.0.[^openai-25]

این دقیقاً همان نقطه‌ای است که معماری Prompt Draft معنا پیدا می‌کند: **مدلی که بهتر می‌تواند جزئیات را حفظ کند، وقتی بهترین نتیجه را می‌دهد که ما هم دقیق‌تر بگوییم چه چیزی باید حفظ شود، چه چیزی باید تغییر کند و چه چیزی اصلاً نباید دست بخورد.**

## Prompt Draft دقیقاً چه مشکلی را حل می‌کند؟

پرامپت‌های تصویری معمولاً با یک مشکل ساده شروع می‌شوند: همه‌چیز در یک متن قرار می‌گیرد.

سوژه، استایل، زاویه‌ی دوربین، نور، حالت صورت، لباس، محیط، نسبت تصویر، محدودیت‌ها و چیزهایی که نباید در تصویر باشند، همگی پشت سر هم نوشته می‌شوند. اگر پرامپت کوتاه باشد، بخشی از نیت کاربر منتقل نمی‌شود؛ اگر بیش از حد بلند شود، احتمال تداخل دستورها بالا می‌رود.

Prompt Draft تلاش می‌کند این وضعیت را به یک ساختار قابل‌مدیریت تبدیل کند.

برای مثال یک خروجی می‌تواند به‌جای یک پاراگراف واحد، چنین منطق شفافی داشته باشد:

```text
{mode} = image to image
{reference_usage} = preserve the main reference while allowing controlled stylistic changes
{preserve} = person's identity
{transformation_strength} = subtle transformation
{aspect} = 9:16

{idea} = ...
{style} = ...
{framing} = ...
{expression} = ...
{pose} = ...
{lighting} = ...
{rules} = ...
```

در ظاهر این فقط قالب‌بندی است، اما در عمل یک تفاوت بنیادی ایجاد می‌کند: **هر تصمیم معنایی جای مشخص خودش را دارد.**

وقتی کاربر می‌گوید هویت چهره باید حفظ شود، این خواسته نباید در میان توضیح نور و استایل گم شود. وقتی می‌گوید تغییر باید subtle باشد، مدل باید این محدودیت را جدا از خود ایده‌ی صحنه دریافت کند. وقتی framing یا expression مهم است، بهتر است به‌صورت یک محور مستقل تعریف شود.

این همان چیزی است که Prompt Draft می‌خواهد استاندارد کند.

> «از اول نمی‌خواستم کاربر یک متن بلند بنویسد و فقط امیدوار باشد مدل منظورش را درست برداشت کند. می‌خواستم هر تصمیم مهم جای مشخص خودش را داشته باشد.»

*این نقل‌قول و نقل‌قول‌های مشابه در این مقاله، بازنویسی تحریری از اصولی هستند که در روند طراحی Prompt Draft دنبال کرده‌ام، نه رونویسی کلمه‌به‌کلمه از یک مصاحبه.*

## اصل اول: ساختار به‌جای Keyword Stuffing

یکی از اشتباه‌های رایج در پرامپت‌نویسی تصویری این است که کیفیت را با تعداد صفت‌ها اشتباه بگیریم.

عبارت‌هایی مثل *cinematic, masterpiece, ultra detailed, 8K, professional, dramatic* اگر بدون نقش مشخص روی هم انباشته شوند، الزاماً کنترل بیشتری ایجاد نمی‌کنند. گاهی فقط نویز معنایی می‌سازند.

Prompt Draft برعکس عمل می‌کند: ابتدا می‌پرسد **چه متغیری واقعاً باید کنترل شود؟**

اگر مسئله composition است، composition باید مشخص شود. اگر مسئله هویت سوژه است، preserve باید روشن باشد. اگر استایل فقط قرار است کمی تغییر کند، transformation strength باید این را بیان کند. اگر یک شیء نباید دیده شود، بهتر است در rules بیاید نه اینکه در انتهای یک پاراگراف گم شود.

در نتیجه هدف، «پرامپت طولانی‌تر» نیست؛ هدف **پرامپت کم‌ابهام‌تر** است.

> «Prompt Draft قرار نیست خلاقیت را محدود کند؛ قرار است ابهام را از مسیر خلاقیت بردارد.»

## اصل دوم: Preserve و Transform باید دو تصمیم مستقل باشند

این اصل مخصوصاً در image-to-image حیاتی است.

کاربر ممکن است بخواهد **هویت شخص کاملاً حفظ شود**، اما هم‌زمان محیط، آب‌وهوا، نور، لباس یا زبان بصری تصویر تغییر کند. در یک پرامپت سنتی، این دو خواسته خیلی راحت با هم قاطی می‌شوند.

Prompt Draft آن‌ها را جدا می‌کند:

- **چه چیزی باید حفظ شود؟**
- **شدت تغییر چقدر است؟**
- **کدام بخش‌ها اجازه‌ی تغییر دارند؟**

این تفکیک با یکی از مهم‌ترین پیشرفت‌های Images 2.5 هم‌راستاست. OpenAI می‌گوید مدل جدید در حفظ سوژه‌های موجود در عکس‌های مرجع بهتر شده و دستورهای ویرایشی را در چند turn قابل‌اعتمادتر دنبال می‌کند.[^openai-25] در System Card نیز به توانایی بهتر مدل برای تغییر setting، style یا composition در حالی که جزئیات بیشتری از تصویر باقی می‌مانند اشاره شده است.[^system-card]

Prompt Draft در چنین مدلی به‌جای اینکه فقط بگوید «این عکس را تغییر بده»، دقیق‌تر مشخص می‌کند **مرز تغییر کجاست**.

## اصل سوم: Reference فقط یک فایل ورودی نیست

در بسیاری از workflowها، reference image به مدل داده می‌شود ولی نقش آن دقیق تعریف نمی‌شود.

آیا مرجع برای هویت است؟ لباس؟ pose؟ palette؟ composition؟ نور؟ یا فقط الهام بصری؟

Prompt Draft تلاش می‌کند **نوع وابستگی به reference** را به بخشی از خود پرامپت تبدیل کند. همین موضوع برای نسل جدید مدل‌های تصویر اهمیت بیشتری دارد، چون هرچه مدل در فهم و حفظ مرجع قوی‌تر شود، تعریف دقیق رابطه‌ی خروجی با مرجع ارزشمندتر می‌شود.

برای مثال:

```text
{reference_usage} =
preserve the main reference while allowing controlled stylistic changes

{preserve} =
person's identity

{transformation_strength} =
subtle transformation
```

سه خط بالا تقریباً یک قرارداد میان کاربر و مدل می‌سازند: «این بخش را نگه دار، این مقدار آزادی برای تغییر داری، و این تصویر صرفاً الهام نیست.»

## اصل چهارم: Composition باید قابل‌توصیف و قابل‌آزمایش باشد

Prompt Draft از ابتدا فقط درباره‌ی «موضوع تصویر» نبود. بخش بزرگی از کنترل واقعی در تصویر از **نحوه‌ی قرار گرفتن عناصر داخل قاب** می‌آید.

مواردی مثل:

**centered / off-center placement، asymmetrical balance، eye-level، low-angle، side view، telephoto framing، amount of subject visible، foreground occlusion و background blur**

همگی می‌توانند در خروجی نهایی بیشتر از چندین صفت استایلی اثر بگذارند.

وقتی این موارد در یک ماژول مستقل قرار می‌گیرند، یک مزیت دیگر هم به‌وجود می‌آید: **تست‌پذیری.**

می‌توان یک batch ساخت که در آن فقط framing تغییر کند و بقیه‌ی prompt ثابت بماند. یا فقط aspect ratio عوض شود. یا تنها transformation strength تغییر کند.

این دقیقاً همان روشی است که Prompt Draft را از یک «prompt builder» ساده به یک **ابزار آزمایش** نزدیک می‌کند.

## چرا GPT‑Image‑2.5 برای این معماری مهم است؟

OpenAI، ChatGPT Images 2.5 را یک مدل state-of-the-art جدید معرفی کرده و به‌طور مشخص از **more precise editing**، **better subject preservation**، نور طبیعی‌تر، texture بهتر و consistency بیشتر در editهای متوالی صحبت کرده است.[^openai-25]

این تغییرات برای Prompt Draft مهم‌اند، چون بخش بزرگی از معماری سیستم حول کنترل همین روابط ساخته شده است.

### ۱. حفظ بهتر هویت، ارزش فیلدهای Preserve را بیشتر می‌کند

در نسل‌هایی که مدل دائماً صورت یا هویت را drift می‌کرد، حتی بهترین دستور preserve هم همیشه نتیجه‌ی قابل‌اعتماد نمی‌داد.

وقتی مدل پایه در این زمینه بهتر می‌شود، دستورهایی مثل:

```text
{preserve} = person's identity
```

دیگر فقط یک درخواست کلی نیستند؛ می‌توانند به یک constraint مؤثرتر تبدیل شوند.

### ۲. ویرایش دقیق‌تر، Rules را مهم‌تر می‌کند

OpenAI یکی از محورهای 2.5 را تغییر دقیق‌تر چیزی که درخواست شده، بدون تخریب ناخواسته‌ی بخش‌های دیگر معرفی می‌کند.[^openai-25]

در Prompt Draft، فیلدهایی مثل:

```text
{rules} =
• keep the subject as the clear focal point
• no photographer, camera, phone, hands, or equipment visible
• blur incidental foreground occlusion
• blur distant background elements
```

همین نقش را دارند: تعیین مرزهای اجرایی.

Rules قرار نیست «negative prompt کلاسیک» باشند. آن‌ها بیشتر شبیه specification هستند.

### ۳. Multi-turn consistency، workflow تکرارشونده را واقعی‌تر می‌کند

Images 2.5 برای editهای چندمرحله‌ای consistentتر طراحی شده است.[^system-card]

این یعنی workflow زیر عملی‌تر از قبل می‌شود:

```text
Reference
→ تغییر محیط
→ اصلاح expression
→ تغییر جزئی framing
→ اصلاح لباس
→ polish نهایی
```

اگر در هر مرحله identity و composition از نو فرو بریزند، چنین workflowای ارزش زیادی ندارد. اما هرچه مدل در حفظ state بهتر شود، سیستم‌های ساختاری مثل Prompt Draft می‌توانند iteration را به بخش اصلی فرایند تبدیل کنند.

### ۴. سرعت بیشتر، آزمایش سیستماتیک را ارزان‌تر از نظر زمان می‌کند

OpenAI از **تا ۵۰٪ latency کمتر نسبت به Images 2.0** صحبت می‌کند.[^openai-25]

این مزیت فقط برای «زودتر گرفتن یک عکس» نیست. برای Prompt Draft، سرعت بیشتر یعنی امکان اجرای batchهای آزمایشی بیشتر:

- ۵ تصویر برای تست composition
- ۵ تصویر برای character consistency
- چند aspect ratio
- چند شدت transformation
- چند variation از یک style

در اینجا سرعت مستقیماً به **سرعت یادگیری از مدل** تبدیل می‌شود.

## Prompt Draft چگونه ایده را به Specification تبدیل می‌کند؟

منطق کلی سیستم را می‌توان این‌طور خلاصه کرد:

```text
ایده‌ی خام کاربر
        ↓
تفکیک تصمیم‌های تصویری
        ↓
ماژول‌های مستقل
        ↓
حل تعارض‌ها و تعیین اولویت‌ها
        ↓
Prompt نهایی
        ↓
مدل تصویر
        ↓
خروجی قابل‌ارزیابی
```

مهم‌ترین بخش، مرحله‌ی وسط است.

برای مثال «یک شخص در باران شدید در خیابان راه می‌رود» هنوز specification نیست.

اما وقتی می‌گوییم:

- شخص آرام راه می‌رود؛
- جمعیت پشت سرش از باران فرار می‌کنند؛
- تضاد احساسی میان سوژه و محیط مهم است؛
- تصویر باید حس candid paparazzi telephoto داشته باشد؛
- observer خارج از کادر بماند؛
- هویت فرد reference حفظ شود؛
- transformation subtle باشد؛
- سوژه off-center باشد؛
- پس‌زمینه و occlusionهای اتفاقی blur شوند؛
- هیچ دوربین یا عکاسی داخل کادر دیده نشود؛

ایده به مجموعه‌ای از **روابط قابل‌اجرا** تبدیل می‌شود.

اینجاست که Prompt Draft بیشترین ارزشش را نشان می‌دهد.

## ماژولار بودن یعنی آزادی بیشتر، نه فرم خشک‌تر

یکی از تصمیم‌های مهم در توسعه‌ی Prompt Draft این بود که ماژول‌ها صرفاً dropdownهای بسته نباشند.

بعضی متغیرها انتخاب‌های استاندارد دارند، اما نیاز واقعی اغلب جایی میان preset و free-form text است. به همین دلیل منطق **module fields with custom descriptive text** اهمیت پیدا کرد: ساختار حفظ می‌شود، اما کاربر همچنان می‌تواند در همان ماژول توضیح خاص خودش را وارد کند.

این تعادل مهم است.

سیستمی که فقط preset دارد، سریعاً محدودکننده می‌شود. سیستمی که همه‌چیز را free text می‌کند، دوباره به همان مشکل اولیه برمی‌گردد.

Prompt Draft بین این دو قرار می‌گیرد:

**ساختار ثابت، محتوای منعطف.**

> «اگر برای آزادی بیشتر تمام ساختار را حذف کنیم، دوباره به یک textbox برمی‌گردیم. هدف این بود که آزادی داخل ساختار اتفاق بیفتد، نه به قیمت از بین رفتن آن.»

## چیزی که Prompt Draft عمداً انجام نمی‌دهد

Prompt Draft قرار نیست تضمین کند که دو generation همیشه یکسان خواهند بود.

مدل‌های تصویر ذاتاً stochastic هستند؛ prompt خوب می‌تواند احتمال رسیدن به نتیجه‌ی مطلوب را افزایش دهد، اما خروجی را به یک renderer قطعی تبدیل نمی‌کند.

همچنین ساختار بیشتر همیشه بهتر نیست. اگر برای یک تصویر ساده ده‌ها constraint بی‌دلیل تعریف شود، خود specification می‌تواند دچار تعارض شود.

به همین دلیل یکی از اصول مهم سیستم این است:

**فقط متغیری را کنترل کن که واقعاً برای نتیجه اهمیت دارد.**

این موضوع در GPT‑Image‑2.5 حتی مهم‌تر می‌شود، چون مدل توانمندتر می‌تواند بخش بیشتری از جزئیات طبیعی را خودش حل کند. Prompt Draft نباید جای مدل تصمیم بگیرد؛ باید نقاطی را مشخص کند که **کاربر واقعاً قصد کنترل آن‌ها را دارد.**

## آیا می‌توان گفت Prompt Draft برای GPT‑Image‑2.5 «بهینه» است؟

از نظر معماری، هم‌راستایی بسیار زیادی وجود دارد.

Prompt Draft روی **reference handling، preserve/transform separation، editing boundaries، composition، style control، constraint clarity و iteration** تمرکز دارد. Images 2.5 نیز دقیقاً در subject preservation، precise editing، multi-turn consistency، detail retention و سرعت iteration پیشرفت کرده است.[^openai-25][^system-card]

اما من ترجیح می‌دهم میان دو جمله تفاوت بگذارم:

**«Prompt Draft با GPT‑Image‑2.5 بسیار سازگار طراحی شده است.»**

و:

**«Prompt Draft به‌صورت علمی ثابت شده که بهترین روش prompting برای GPT‑Image‑2.5 است.»**

اولی را می‌توان با طراحی سیستم و قابلیت‌های رسمی مدل توضیح داد. دومی فقط با benchmark کنترل‌شده قابل اثبات است.

و اتفاقاً مرحله‌ی بعدی جذاب Prompt Draft همین‌جاست: تبدیل تجربه به داده.

## مرحله‌ی بعد: Prompt Draft به‌عنوان آزمایشگاه پرامپت

یکی از مسیرهای طبیعی پروژه، ساخت experimentهای کنترل‌شده است.

به‌جای مقایسه‌ی دو تصویر تصادفی، می‌توان یک batch تعریف کرد که فقط **یک متغیر** در آن تغییر کند:

```text
Test A → Style
Test B → Composition
Test C → Aspect Ratio
Test D → Character Consistency
Test E → Transformation Strength
```

بعد خروجی‌ها با یک checklist ثابت ارزیابی شوند:

- Prompt adherence
- Identity preservation
- Composition accuracy
- Unwanted changes
- Material / texture quality
- Lighting quality
- Character consistency
- Visual coherence

در این مرحله Prompt Draft فقط ابزار تولید prompt نیست؛ تبدیل می‌شود به ابزاری برای **فهم رفتار مدل‌های تصویر**.

## نتیجه‌گیری

GPT‑Image‑2.5 نشان می‌دهد که نسل جدید مدل‌های تصویر دارد از «ساخت یک تصویر زیبا از یک توضیح» عبور می‌کند و به سمت **ویرایش دقیق، حفظ مرجع، iteration و کنترل بیشتر** می‌رود.

برای من، Prompt Draft از ابتدا حول همین مسئله ساخته شد.

هدف این نبود که طولانی‌ترین prompt ممکن تولید شود. هدف این بود که **intent به specification تبدیل شود**؛ مشخص شود چه چیزی هسته‌ی تصویر است، چه چیزی قابل‌تغییر است، چه چیزی باید حفظ شود و کدام تصمیم‌ها باید مستقل از یکدیگر قابل‌کنترل باشند.

هرچه مدل‌های تصویر بهتر می‌شوند، اهمیت این ساختار کمتر نمی‌شود؛ برعکس، ساختار خوب اجازه می‌دهد از توانایی‌های جدید مدل استفاده‌ی دقیق‌تری کنیم.

شاید بهترین تعریف Prompt Draft همین باشد:

> **Prompt Draft یک ماشین تولید کلمات نیست؛ یک لایه‌ی طراحی میان ایده‌ی انسان و مدل تصویر است.**

و با GPT‑Image‑2.5، این لایه از همیشه کاربردی‌تر به نظر می‌رسد.
