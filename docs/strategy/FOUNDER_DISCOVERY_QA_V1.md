# Prompt Draft — Founder Discovery Q&A V1

Status: **Decision record / founder-intent source**

Purpose: preserve the reasoning, uncertainty and product philosophy that produced `PRODUCT_STRATEGY_V1.md`.

This is not a technical implementation spec. When future choices become ambiguous, use this document to recover the original founder intent before optimizing for local implementation convenience.

---

# 1. Long-term vision

**Question:** If Prompt Draft succeeds in five years, what should people associate with the name?

**Founder answer:** A reference point for using AI in any field, especially for people who are not prompt engineers and want to accomplish work more easily. Image generation is only the first field. Users should be able to start from reusable templates/products and customize them. For prompt engineers and AI specialists, Prompt Draft should also become a place for education, personal branding and income.

**Decision:** Consumer utility and Creator economy are both core to the long-term platform.

---

# 2. Why Prompt Draft instead of a prompt list or education site?

**Founder answer:** Static prompt lists are weak because the prompts are not meaningfully editable/customizable. Education sites are incomplete because learning and implementation are separated. Prompt Draft should teach concepts where appropriate while giving the user the implementation surface in the same module/workflow.

**Decision:** Prompt Draft is both a learning/playground environment and a structured execution-preparation system.

---

# 3. First target personas

**Founder answer:** In the current product state, priority users are AI designers/artists, business owners and then prompt engineers/Creators. At future marketplace scale, the most strategically important persona becomes the prompt engineer/Creator because their activity creates the marketplace supply.

**Decision:** Current go-to-market begins with AI visual creators/users, but Creator acquisition becomes the long-term strategic bottleneck.

---

# 4. Core value for expert vs consumer

**Founder answer:** For an expert, the value is turning an idea into an organized structured prompt, keeping it permanently available in an account, and using/remixing other users' work. For a consumer, the value is finding something close to the need and applying minimum changes without understanding prompt engineering.

**Decision:** There are two connected loops:

```text
Expert -> Build -> Save -> Reuse -> Publish
Consumer -> Discover -> Customize -> Use
```

---

# 5. What does a Creator publish/sell?

**Founder answer:** Prompt, structured prompt, template, workflow and education can all be valid. The higher-level point is to let the prompt engineer present their craft, build a personal brand and make money.

**Decision:** The marketplace must not be modeled as a file store. Creator identity is as important as the product unit.

---

# 6. Prompt Draft's place in the AI stack

**Founder answer:** Prompt Draft must never become the final AI destination. The product is the intelligent layer before external AI tools. It converts user intent into logically engineered AI instructions. It should not compete with ChatGPT, Krea, Midjourney or model providers.

**Decision:** Prompt Draft owns preparation/orchestration, not final model execution.

---

# 7. Domain expansion

**Founder answer:** Long-term category scope is intentionally open. Current expected next priorities after Image / Visual Creation are Content Creation, Programming, Education and Marketing/Advertising. Categories should be able to grow based on real market demand rather than a permanently fixed taxonomy.

**Decision:** Horizontal domain expansion; market-responsive taxonomy.

---

# 8. Quality control

**Founder answer:** User feedback should be the main quality signal. Prompt Draft cannot manually review an unlimited catalog. Usage, remix, ratings and other behavior matter. Analytics must allow the platform to test whether its own reputation algorithms actually correlate with value.

**Decision:** Prompt Draft is not the absolute quality gatekeeper. Market behavior is primary.

---

# 9. Creator economics

**Founder answer:** Direct sales should pay a percentage to Prompt Draft. Creators should also receive reputation/reward value from actions such as product usage, copy, remix and traffic they bring. Pricing should remain free. A Creator may publish only for portfolio/personal branding and never monetize.

**Decision:** Monetization is optional; Creator profiles must work in portfolio-only mode.

---

# 10. Consumer journey

**Founder answer:** A normal user should ideally enter through a simple guided flow/wizard and receive relevant data/products quickly. The homepage should become personalized from explicit interests and later implicit behavior. A normal user should not need to know prompt-engineering internals.

**Decision:** Intent-first guided experience with personalized discovery.

---

# 11. AI inside Prompt Draft

**Founder answer:** AI should not replace the semantic system by taking a raw idea and returning arbitrary better prose. AI should map intent into Prompt Draft modules/fields/options and help express values that are not already represented in fixed choices. Structured user trees can become future training data. Dynamic Wizard steps may eventually be generated with AI but must operate through the existing validated action/schema system. AI quality scoring is not an immediate priority.

**Decision:** AI-enhanced, not AI-defined. Structured semantics remain authoritative.

---

# 12. Go-to-market hypothesis

**Founder answer:** Referral can be a major first-year growth engine. SEO should run in parallel. Creator outreach/community activity may be required. Paid acquisition is not the primary early strategy.

**Decision:** Referral + SEO + Creator-led distribution are the initial growth hypotheses.

---

# 13. MVP/current readiness

**Founder answer:** The product has already completed extensive core engineering. The immediate problem is no longer building a basic editor. The existing system can already exceed a normal MVP after production deployment and the final commercial/growth gaps are filled.

**Decision:** Stop treating Prompt Draft as an early prototype. Audit and activate existing capabilities.

---

# 14. Competitive moat

**Founder answer:** The strongest moat is the Semantic Prompt Engine and the reusable engineering method behind it. The second major moat should be Creator identity and reputation: specialists should want to point others to Prompt Draft as their public professional reference.

**Decision:** Technical moat + network/identity moat.

---

# 15. What is actually being sold?

**Founder answer:** A prompt should not be understood as merely text. It represents strategy, knowledge, data and engineering decisions. Even if future AI interaction formats change and the industry stops calling the artifact a prompt, the underlying product remains reusable engineering knowledge.

**Decision:** Brand/product model should outlive today's text-prompt format.

---

# 16. Remix ownership

**Founder answer:** The original Creator should control whether others may remix, publish or sell derived versions. Derived products should identify the original product. The original Creator may define pricing/revenue-share constraints. A derived sale may pay part of revenue back to the source Creator.

**Decision:** Permission-based remix economy with attribution and lineage.

---

# 17. Product/data ownership

**Founder answer:** The Creator remains owner of the commercial product and Prompt Draft must not independently resell that product without paying the Creator's defined economic value. Products created/sold through Prompt Draft should not be sold externally in ways that bypass the platform agreement. Prompt Draft may use anonymized structural/platform data to improve its future internal intelligence and this must be disclosed clearly.

**Decision:** Creator owns sellable knowledge; Prompt Draft owns platform intelligence.

---

# 18. Trust signals

**Founder answer:** Verified Creator matters. Real output/examples build trust. Raw sales count is not enough; views, conversion and context matter. Buyers who actually used the product should rate it. Creator reputation should reflect the performance/rating of their catalog. Prompt Draft may separately recommend high-quality products.

**Decision:** User evidence + automated reputation + separate editorial promotion.

---

# 19. Marketplace cold start

**Founder answer:** Initial financial resources may not support paying many known Creators. Seed the system with several strong initial Creator identities, including founder-operated accounts if necessary, plus a small number of external Creators. If usage shows demand, later invest in paid Creator acquisition or a content-production team.

**Decision:** Controlled seed marketplace before organic scale.

---

# 20. Year-1 success metrics

Founder-selected top three:

1. Creator count
2. Product/prompt usage broken down by copy, remix and copy-link/share
3. Product count

**Decision:** Ecosystem activity before short-term revenue as the primary proof.

---

# 21. What Prompt Draft should not become

**Founder answer:** Do not vertically expand into unrelated execution businesses. Grow horizontally by adding more prompt generators/domains under the same semantic-engine logic.

**Decision:** No AI super-app strategy.

---

# 22. Roadmap ordering

Founder-selected order:

```text
1. Growth Foundation
2. Domain Expansion
3. Marketplace Activation
4. AI Enhancement
```

The founder believes the technical core is already strong and the next important work is making the company attractive to accelerators/investors by demonstrating growth and circulation.

---

# 23. Growth vs control

**Founder answer:** Prefer slower growth while preserving engineering identity and product quality.

**Decision:** Quality/identity before uncontrolled scale.

---

# 24. Biggest failure risk

**Founder answer:** Failure to attract Creators.

**Decision:** Creator acquisition must become an explicit strategic workstream.

---

# 25. Founder North Star

Founder phrase:

> «آیا این تجربه قابلیت ری‌یوز دارد؟ اگه داره تجربه‌مو می‌فروشم.»

Interpretation: reusable experience is productizable knowledge.

---

# 26. Marketplace unit: finished products or composable pieces?

**Founder answer:** Definitely composable knowledge pieces. This has been the logic of Prompt Draft from the beginning. Treat each knowledge unit like a module that can be placed on a board and connected into a logically working circuit. Modules should not need to care about the internal behavior of unrelated modules.

**Decision:** Marketplace architecture must support composition, not only standalone listings.

---

# 27. Knowledge lineage

**Founder answer:** The founder wants the history/evolution of knowledge to remain accessible, provided the backend/data cost is reasonable.

**Decision:** Preserve lineage. Start with simple PostgreSQL relationships; do not overengineer a graph database early.

---

# 28. Creator-to-Creator community

**Founder answer:** Following Creators is valuable and supports growth without violating the horizontal-product strategy. Both users and Creators should be able to follow Creators. Follow data should improve homepage suggestions and new-content feeds.

**Decision:** Community/follow graph is future horizontal infrastructure.

---

# 29. Search vs discovery

**Founder answer:** Intent-first is the preferred model.

**Decision:** Users should express a goal and Prompt Draft should surface the right knowledge/product type rather than forcing prompt-centric search language.

---

# 30. Execution/orchestration layer

**Founder answer:** Prompt Draft should finalize a product for the user's context before handoff. Example: modify aspect ratio, fill poster title/date/description variables, choose controlled options and copy the finalized output without opening the full editor.

**Decision:** Execution Layer is a core value surface and can itself justify payment.

---

# 31. What is the user paying for?

**Founder answer:** The founder values the technical/engineering work, but users pay for reduced human cost: less thinking, less setup, less staffing and faster progress toward a result. At company scale, a good workflow can reduce entire repetitive human processes.

**Decision:** Price should follow saved human effort and value/impact, not implementation complexity.

---

# 32. Product type vs value-based pricing

**Founder answer:** Use a hybrid model. Product type provides a baseline/context but the Creator sets price based on perceived value. Prompt Draft should show market data for comparable products of the same type/category: average, low/high range and related statistics.

**Decision:** Creator-controlled pricing with marketplace pricing intelligence.

---

# 33. Credit as payment wrapper or economy?

**Founder answer:** The founder wants a real incentive/economic mechanism inside Prompt Draft, potentially with its own named internal coin. Purchases inside the platform should use this unit. The inspiration is the engagement dynamics of giveaway/token-style products, but Prompt Draft should not create a legal cryptocurrency.

**Decision:** Virtual internal economy, not external tokenization.

---

# 34–35. Creator payout and early coin availability

**Founder answer:** Early phase should simulate the economy by distributing units through activity for months before requiring real-money purchases. At the end of a successful experiment, retained balances could become usable real platform value; Creators may be able to cash out based on an established conversion value. Investor capital may help fund this transition/reward pool if growth evidence justifies it.

**Decision:** Simulation economy first; real conversion/purchase later, after circulation is proven.

---

# 36. Which actions cost value?

**Founder answer:** Not every UI action should be charged. Discovery should remain free. First meaningful extraction can cost value. Example: first copy of a prompt may cost once; subsequent copies of the same already-unlocked product should not repeatedly charge. Personalization/customization can carry a cost because the user is consuming the Execution Layer. Repeated personalization may be chargeable.

**Decision:** Charge value extraction, not browsing friction.

---

# 37. Normal access vs full ownership

**Founder answer:** Most users need normal usage/access. Full exclusive ownership is different: if purchased, the product should move under the buyer's control. Management settings, future sales and product administration move to the new owner while historical attribution/lineage remains.

**Decision:** Full ownership transfer is a real marketplace action, not merely a license label.

---

# 38. Creator monetization models V1

Founder-selected models:

```text
1. Free
2. One-time purchase
3. Full product ownership transfer
```

Subscriptions and pay-per-use are deferred because they add complexity before the base marketplace loop is proven.

---

# 39. Platform commission

**Founder answer:** If only founder preference mattered, Prompt Draft could simply cover infrastructure costs and be extremely Creator-first. But the company must also be financially attractive to accelerators/investors. Therefore the product should feel Creator-first while still operating as a commission marketplace. Use a base percentage and reward strong Creators with lower commission.

**Decision:** Clear base commission minus reputation/level discounts.

---

# 40. Creator reputation

**Founder answer:** Most reputation must be automatic. Prompt Draft Recommended should not manipulate objective lists such as Most Viewed. Editorial recommendations should live in a separate surface. Prompt Draft is not the quality gatekeeper, but it can be a promotion/recommendation gatekeeper.

**Decision:** Separate objective ranking from editorial promotion.

---

# 41. Creator Level

**Founder answer:** Creator Level should affect the economy directly through commission reduction. Visually levels are badges. Admin/Creator-panel capability should not differ by level. Homepage ranking should use separate filtered algorithms. Creator terms must be extremely clear; contract complexity discourages Creators.

**Decision:** Level = economic incentive, not hidden privilege system.

---

# 42. Performance-data ownership

Founder principle:

> «مالکیت اون بخشی از داده که فروشی نیست (شامل دانش فنی و مهندسی نیست) برای پرامپت درفت محفوظه»

Interpretation: sellable engineering knowledge remains Creator-owned, while non-sellable ecosystem intelligence belongs to Prompt Draft.

---

# Data retention clarification

**Founder answer:** Internal platform data does not disappear when a Creator removes the commercial product. The Creator may remove the sellable/public portion according to the product rules, but cannot delete Prompt Draft-owned platform intelligence. Analysis should ultimately be anonymized.

The founder noted that related retention behavior already exists in the current backend branch and must be audited/reused rather than rebuilt.

---

# Multi-owner products

Multi-Creator ownership/revenue sharing is acknowledged as a likely future requirement, but the founder explicitly does **not** want to solve it now.

**Decision:** Deferred. Do not let speculative multi-owner architecture expand the immediate milestone.

---

# Additional architecture discussion — static rendering and future marketplace scale

Current Prompt Draft deployment uses static Nuxt generation and an independent backend API.

The founder agrees that this remains appropriate for the present product, while a future very large public marketplace may require a rendering/deployment transition for SEO and dynamic content.

Potential future options:

- static generation where bounded;
- incremental regeneration;
- SSR;
- hybrid rendering.

The likely conceptual direction is public content optimized for server/prerender SEO while private application surfaces stay client-oriented.

**Decision:** Record the architectural decision now; do not migrate rendering strategy before real scale/SEO requirements justify it.
